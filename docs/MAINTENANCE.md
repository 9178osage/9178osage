## 部署与更新

主页位于公开仓库 [9178osage/9178osage](https://github.com/9178osage/9178osage)，默认分支为 `main`。初版取代了 GitHub 的初始欢迎模板，经本人授权后发布到 `main`。

以后更新时：

1. 修改三个 README 或 `assets/`，同步检查文案、邮箱、插画和变更。
2. 运行下面的本地检查；联网检查会访问文档中的公开链接。
3. 提交后推送到 `main`（或通过 PR 合并到 `main`）。GitHub 网页上传也会直接创建提交。
4. 打开 [个人主页](https://github.com/9178osage)，核对英文入口、中文和日文导航、浅色与深色主题以及手机显示。
5. 确认 `assets/` 已一起发布。如果图片缺失，优先检查大小写、相对路径和默认分支上的文件，而不是引入外部图片服务。

**不需要** GitHub Pages、Vercel、域名、构建步骤、API 密钥、统计服务或定时工作流。公开同名仓库根目录中的 `README.md` 由 GitHub 自动展示。若以后迁移到尚不存在的同名仓库，先创建公开的 `9178osage/9178osage`，再放入相同文件。

## 检查方式

需要 Python 3.9 或以上；联网检查另需 `curl`：

```bash
python3 scripts/check_profile.py
python3 scripts/check_profile.py --online
git diff --check
```

检查工具覆盖三语项目顺序、必须保留的支持语句、Markdown 与 HTML 图片替代文本、相对文件路径、导航锚点、SVG XML、独立资源、尺寸预算和减弱动态设置。`--online` 对唯一 HTTPS 链接执行带超时的 HEAD 请求，失败会明确报错，不会当作通过。

这些是有边界的检查，不是通用 Markdown 解析器或安全审计：修改复杂 Markdown 时仍需查看 GitHub 渲染结果；HTTP 成功不代表登录、留言、下载内容或网站全部功能已经验收。邮箱只检查链接格式和地址，不测试投递。公开主页最终效果需在获准发布后确认。

## GitHub 渲染与可访问性

- 页面正文使用 GitHub 原生 Markdown 和简单的 `p`、`a`、`img`、`h1`、`strong`、`em`、`br`、`sub` 标签，无脚本、iframe、内联 CSS 或自定义布局。
- 单列排版，不用固定宽度表格。图片有 `viewBox`，顶部图片为容器宽度，其余图片由 GitHub 原生样式约束。
- 正文跟随 GitHub 主题；插画使用不透明的深蓝底和浅色文字，在明暗主题中保持自己的对比度。不依靠透明底上的固定文字颜色，也不依赖系统主题与 GitHub 主题同步。
- 插画中的标题仅为装饰，身份、项目名称、功能和入口都另有正常文本。三语版本各有对应语言的图片替代文本。
- 数学公式使用 GitHub 支持的 `$...$`。奇数求和公式注明正整数范围，图中的 1、3、5、7 个方格区域组成 4×4 正方形；不暗示作者的数学资历。
- 唯一动画是 `music-corner.svg` 中 9 秒一周期、9 个 SVG 单位幅度的轻微雨滴漂移。仅在 `prefers-reduced-motion: no-preference` 时启动；请求减少动态、禁用动画或不支持 CSS 动画时，保留完整静态插画。
- 不嵌入音乐播放器，也不伪造 “now playing” 或听歌记录。不使用访问计数器、统计卡片、外部字体或徽章图片服务。
