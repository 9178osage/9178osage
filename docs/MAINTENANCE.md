## 部署与更新

主页位于公开仓库 [9178osage/9178osage](https://github.com/9178osage/9178osage)，默认分支为 `main`。初版取代了 GitHub 的初始欢迎模板，经本人授权后发布到 `main`。

以后更新时：

1. 在 `README.md` 对应的语言折叠区修改正文；修改中文或日文时，同步更新对应的独立副本。检查三语文案、项目链接、免责声明和隐私信息。
2. 运行下面的本地检查；联网检查会访问文档中的公开链接。
3. 提交后推送到 `main`（或通过 PR 合并到 `main`）。GitHub 网页上传也会直接创建提交。
4. 打开 [个人主页](https://github.com/9178osage)，核对英文默认展开、中文和日文点击后在同页展开与收起、章节导航、浅色与深色主题以及手机显示。
5. 顶部头像直接引用 GitHub 账号头像，会随账号头像变化。若以后加入其他图片，放在仓库内的 `assets/` 并用相对路径引用，确认它们一起发布。图片缺失时，优先检查大小写、相对路径和默认分支上的文件，而不是引入外部图片服务。

**不需要** GitHub Pages、Vercel、域名、构建步骤、API 密钥、统计服务或定时工作流。公开同名仓库根目录中的 `README.md` 由 GitHub 自动展示。若以后迁移到尚不存在的同名仓库，先创建公开的 `9178osage/9178osage`，再放入相同文件。

## 检查方式

需要 Python 3.9 或以上；联网检查另需 `curl`：

```bash
python3 scripts/update_contributions.py
python3 scripts/check_profile.py
python3 scripts/check_profile.py --online
git diff --check
```

检查工具覆盖三语项目顺序、必需的个人主站与项目链接、允许的 HTML 标签、相对文件路径和导航锚点，也检查语言折叠区的闭合、顺序、默认展开状态、无跨文件语言导航，以及中文和日文正文与独立副本的一致性；比较时会跳过独立副本顶部的头像和标题。工具还会阻止把邮箱地址或即时通讯号码重新写回主页。README 若以代码围栏开头，会明确报错，避免把整篇介绍误写成代码块。图片需要替代文本；若以后加入 `assets/` 中的 SVG，还会检查 XML、独立资源、尺寸预算和减弱动态设置。`--online` 对唯一 HTTPS 链接执行带超时的 HEAD 请求，失败会明确报错，不会当作通过。

这些是有边界的检查，不是通用 Markdown 解析器或安全审计：修改复杂 Markdown 时仍需查看 GitHub 渲染结果；HTTP 成功不代表登录、留言、下载内容或网站全部功能已经验收。公开主页最终效果需在发布后确认。

## GitHub 渲染与可访问性

- 页面正文使用 GitHub 原生 Markdown 和简单的 `p`、`img`、`a`、`h1`、`strong`、`em`、`br`、`sub`、`details`、`summary` 标签，无脚本、iframe、内联 CSS 或自定义布局。语言折叠区的摘要可通过键盘聚焦并展开。
- 正文采用单列排版，不用固定宽度表格；顶部显示 GitHub 账号头像。观测站和 Eugene Desk 使用 640 px 宽的真实主页截图，桌宠项目使用已有角色图，音乐板块并排展示两张静态图片。
- 正文完全跟随 GitHub 的浅色与深色主题，没有固定颜色的文字。
- 身份、项目名称、功能和入口都是正常文本；头像带有替代文本。
- 不嵌入音乐播放器，也不伪造 “now playing” 或听歌记录。不使用访问计数器、统计图片、第三方统计卡片、外部字体或徽章图片服务。
